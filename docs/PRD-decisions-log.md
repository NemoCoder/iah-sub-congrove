## ③ 协商时间

### ★3.1 项目分「团队 / 个人」两类——这条改写了隐私模型★

| 项目类型 | 它的会议/日程产生的忙闲 | 用途 |
|---|---|---|
| **团队项目** | **全平台可见**（只有忙/空，无任何内容） | 正常协作 |
| **个人项目** | ★**完全隐形**★——别人看到的是"空闲"，发起人**不知道我忙** | 私事、个人提醒、个人统计 |

**这取代了 PRD v0.2 里「逐条标记某日程不占用忙闲」的设计**——按项目类型自动分流，
用户不用每次记得去勾。

**随之而来的关键推论**：私事冲突时，**发起人根本不知道我忙**，所以

- 系统必须**醒目提醒我本人**（3.4）
- 我只能**自己去协调** → 这就是「建议改期」和「私聊」存在的理由

**模型简化**：个人日程 = 个人项目里的会议。PRD 里那张 `personal_events` 表**可以删掉**。

| # | 结论 |
|---|---|
| 3.2 | 「团队项目全平台可见」**仅指忙闲**；**项目名称与成员名单不公开** |
| 3.3 | 个人项目：**每人自动建一个「我的日程」，也允许再建**多个 |
| 3.4 | 有人约我、而我那时有**个人日程** → ★**醒目提醒我本人**★（否则必漏） |
| 3.5 | 个人项目**能存材料**，完全私密（兼作个人网盘） |
| 3.6 | 应答**四态并列**：接受 / 拒绝 / 待定 / **建议改期** |
| 3.7 | 一直不应答：**发起人可手动催办**（不自动催） |
| 3.8 | 会议发出后，**发起人 + 项目主持人/管理员**可修改 |

### ★3.9 新增：会议讨论区★

| 频道 | 谁能看 | 谁能发 | 通知 |
|---|---|---|---|
| **公开讨论** | 参会人（含临时参会人） | 同左（**旁听者不能发**，防刷屏） | 只标未读，不发站内信 |
| **私聊** | 仅双方 | 可私聊**发起人 + 项目主持人** | ★**必发站内信**★（改期协商往往是急事） |

- 聊天记录**保留在会议详情页，不进材料**（不占项目目录、权限跟会议走）
- ★**边界**：私聊对象**只限这两个角色**，不做任意点对点——否则会长成一个 IM

## ⑥ 会后沉淀

### ★6.1 纪要的定位被整个纠正★

| | 原设计（错） | 实际要的 |
|---|---|---|
| AI 转写/纪要 | **最终产物**，大家直接看 | ★**原材料**，供记录员核对整理★ |
| 正式纪要 | 就是 AI 那份 | ★**人按固定格式写的**，有明确责任人★ |
| 录屏/材料 | 归档留存 | ★**帮记录员核对整理的依据**★ |

**流程**：

```
发起会议时 → ★指定本次会议的纪要负责人（记录员）★
   ↓
会后 → 参会人把录屏/录音/资料都传上来
   ↓
系统 → 自动转写 + 生成参考稿（★工具，不是成品★）
   ↓
记录员 → 对照材料，按★固定模板★整理出正式纪要
   ↓
点「完成」→ ★生成 PDF 存档★ + 通知全员
```

| # | 结论 |
|---|---|
| 6.2 | **记录员在发起会议时必填**（默认可填发起人自己，随时可改） |
| 6.3 | 纪要模板：★**先只做一种通用模板**★，日后按新需求再增（2026-08-06 修正，原为「多套内置」） |
| 6.4 | 通用模板字段：主题 / 时间 / 地点 / 所属项目 / 主持人 / 记录人 / 参会人 / 旁听人 / 缺席人 / 议题 / 主要内容 / 决议事项 / 待办事项 / 下次会议时间 |
| 6.4b | ★字段要**通用到能覆盖各类会议**★——因为只有一种模板,用不上的字段留空即可,**不为某类会议做特化** |
| 6.5 | 参会人、旁听人名单**系统带出邀请名单，记录员核对修改**（这就是"补录实际到场"） |
| 6.6 | 「待办事项」**先当普通文本写**，★不做结构化任务系统★（防止范围膨胀） |
| 6.7 | 纪要**两态：草稿 / 已完成**；完成后通知全员 |
| 6.8 | 纪要**所有参会人都能编辑**（有版本历史 + 一键恢复兜底） |
| 6.9 | 多人各录一份 → **材料都保留，只对最长的那份生成参考稿**（避免重复耗 GPU、避免两份纪要） |

### ★7.5 新增：纪要 PDF 走 LaTeX★

| # | 结论 |
|---|---|
| 7.5.1 | 记录员写 **Markdown**，系统**转 LaTeX 套模板**出 PDF |
| 7.5.2 | PDF 生成时机：★**点「完成」时生成并存档**，之后修改可**重新生成新版本**★（进版本历史） |
| 7.5.3 | 渲染失败 → ★**报错并附日志片段**，绝不静默★（要能告诉记录员第几行有问题） |
| 7.5.4 | ★**已向平台提议：起一个共享的 LaTeX 编译服务**★（群消息 #118，见下） |

**为什么要共享服务而不是各装各的**：

| 各子系统自装 | 平台共享服务 |
|---|---|
| 每镜像 +800MB~1.5GB，N 家 ×N 份 | 一份 |
| 构建要走镜像源装 TeX（congrove 曾因 900s 死线挂过构建） | 子系统镜像回到几十 MB |
| 字体/宏包版本各不相同 → PDF 观感不统一 | 全平台统一 |

★**必须在第一版就锁死的安全边界**★（已在提议里写明）：LaTeX 图灵完备、能读写文件、能执行 shell
（`\write18`、`\input{/etc/passwd}`）——**"提交源码就编译"本质是远程代码执行接口**。
要求：禁 shell-escape、`openin_any=p`/`openout_any=p`、**无网络**、wall-clock 超时、
只读根文件系统 + 临时空目录、输入输出限大小。
