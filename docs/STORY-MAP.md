## 0. 这份文档解决什么问题

PRD 按模块写（日历 / 会议详情 / 归档 / 统计），那是**系统视角**。
但人用它是按时间流动的，是**旅程视角**。两者不换算一遍，就会出现典型的失败：

> 「功能都做完了，但用户第一步就卡住了。」

故事地图把功能沿旅程铺开，然后**横着切**。每一刀就是一期，检验标准只有一条：

> ★**切完这一刀，用户能不能从头到尾做成一件事？**★

## 1. 骨干：一次会议的完整旅程

```
 ①组建项目 → ②发起会议 → ③协商时间 → ④会前准备 → ⑤开会 → ⑥会后沉淀 → ⑦查阅复用 → ⑧复盘统计
```

每个阶段下的任务，按「不做就走不通」到「锦上添花」从上往下排：

| ①组建项目 | ②发起会议 | ③协商时间 | ④会前准备 | ⑤开会 | ⑥会后沉淀 | ⑦查阅复用 | ⑧复盘统计 |
|---|---|---|---|---|---|---|---|
| 建项目、定主持人 | 填标题/时间 | 看参会人忙闲 | 传会前材料 | 从日历拿链接 | 传录屏/录音 | 项目入口浏览 | 个人月/季/年统计 |
| **批量**加成员 | 写议题与议程 | 冲突提示 | 改线上链接 | 旁听者从公开列表进 | **自动**转写出纪要 | 时间线入口回溯 | 项目统计（去重） |
| 指定管理员 | 选参会人 | 接受/拒绝/待定 | 看谁应答了 | | 补录实际到场 | 复制到自由区整理 | 时长口径展示 |
| 移出成员 | 关联项目(1..N) | **建议改期** | 收到变更通知 | | 设禁下载/禁分享 | 生成公开分享链接 | 导出 CSV |
| （移出→撤链接） | 设周期规则 | 采纳/驳回改期 | | | | 只读会议区 | 旁听人次 |
| | 设公开/私密 | | | | | | |

## 2. 切片：五期，每期都是一个能走通的闭环

### ★M1 —— 「能把会约成」★

**这一刀之后，用户能完整做成的事**：建一个项目 → 拉人进来 → 发起一次会议 → 看到谁有冲突 → 大家应答 → 到时间从日历里点开链接去开会。

| 阶段 | M1 包含 |
|---|---|
| ①组建项目 | 建项目、定主持人、**批量加成员**、指定管理员 |
| ②发起会议 | 标题/时间/**议题议程**/**线上链接与线下地点**/选参会人/关联项目 |
| ③协商时间 | 忙闲查询、冲突提示、接受/拒绝/待定 |
| ④会前准备 | —（材料在 M3） |
| ⑤开会 | **会议详情页**（看时间、议程、链接）、个人日历（日/周/月/列表） |
| 附带 | 个人日程（非会议的忙碌时间）、站内信通知 |

> ⚠ **故事地图在这里发现了 PRD 分期的第一个断点**：
> PRD 原本把「会议详情页」放在 M3。但没有它，M1 约完会**看不到线上链接**，
> 到点了不知道去哪开——流程断在第 ⑤ 步。**会议详情页必须提前到 M1**（只是那时它还没有材料区）。

**验收这一期的唯一标准**：一个新人能在不问任何人的情况下，把一次会约成并如期开上。

---

### M2 —— 「能处理冲突和长期安排」

**新增能做的事**：撞车了能协商解决；组会一次设好不用每周发；把会公开出去让别人来听。

| 阶段 | M2 新增 |
|---|---|
| ②发起会议 | **周期规则**（每周三 15:00…）、设公开/私密 |
| ③协商时间 | ★**建议改期**（COUNTER）★、采纳/驳回、改期后全员重新应答 |
| ⑤开会 | **公开会议广场**、旁听（占忙闲） |
| ①组建项目 | 移出成员 |

---

### M3 —— 「材料有地方放，纪要自动出」

**新增能做的事**：会前把要讨论的东西传上去；会后传录屏，**纪要自动生成**，不用人写。

| 阶段 | M3 新增 |
|---|---|
| ④会前准备 | 会前材料上传、改线上链接（**通知全员**）、看应答情况 |
| ⑥会后沉淀 | 会后材料上传（**任何参会人都能传**）、★自动转写 + 生成纪要★ |
| ⑦查阅复用 | 项目树里的**只读会议区**（`会议/2026-08-06 xxx/`） |

> 这一期**大量复用现有能力**（大文件直传、断点续传、秒传、转写、纪要），
> 真正的新工作是「会议 ↔ 材料」的关联和只读区的呈现。性价比最高的一期。

---

### M4 —— 「找得到、整理得了、分享得出去」

**新增能做的事**：三个月后还能找到那次会的东西；主持人把多次会议的材料重新分门别类；把材料发给外面的人。

| 阶段 | M4 新增 |
|---|---|
| ⑦查阅复用 | ★**时间线入口**★、**复制到自由区**整理、公开分享链接 |
| ⑥会后沉淀 | 材料权限开关（禁下载 / 禁分享） |
| ①组建项目 | ★**移出成员时连带撤销其公开链接**★（D3 硬要求，有了分享才有意义） |

---

### M5 —— 「季度汇报有数据」

| 阶段 | M5 新增 |
|---|---|
| ⑥会后沉淀 | **补录实际到场**（含旁听者姓名，写进纪要） |
| ⑧复盘统计 | 个人统计、项目统计（分组展开 / 总计去重）、**时长口径来源展示**、导出 CSV、旁听人次 |

> 放最后是对的——**没有数据积累的统计页是空的**。M1~M4 跑几个月，M5 才有东西可看。

## 3. 故事地图查出来的问题

这才是做这份地图的收获。按严重程度排：

### ★问题 1：会议详情页的分期错了（已在上面修正）★

PRD 把它放 M3，但 M1 就需要——**约完会看不到链接，流程断在「去开会」这一步**。
**处置**：提前到 M1，作为「只有信息、没有材料」的简版。

### ★问题 2：会议可以不关联任何项目吗？PRD 没说★

全所大会、跨项目临时讨论，未必属于某个项目。但 D3 规定权限来自项目成员身份——
**不关联项目的会议，它的材料归谁管、谁能看？**

**我的建议**：允许不关联项目，但这种会**不能上传材料**（等同于「只有日程，没有沉淀」）；
若要沉淀，必须先关联一个项目。这样 D3 不用开任何特例。
→ **待你拍板**（已补进 PRD 开放问题）。

### 问题 3：M1 的「批量加成员」不是可选项

D12 删掉了「小组」，加人只能到人。若 M1 不做批量，第一个项目拉 20 人要点 20 次——
**第一次使用就是最差体验**。已在 PRD 风险表标注，此处再确认：**批量加人是 M1 的必做项**。

### 问题 4：⑤「开会」这一列几乎是空的

我们不做会中功能（PRD §1.3 明确不做），所以这一列只有「拿到链接」。
**这是刻意的**，不是遗漏——记在这里免得后面有人以为漏了。

### 问题 5：M3 之前，会议详情页有「材料」入口但点不了

M1/M2 上线时，用户会问「材料在哪传」。
**处置**：M1/M2 的会议详情页**不要显示材料区**（而不是显示一个禁用的按钮），
等 M3 再出现。少一个「这个功能坏了吗」的疑问。

## 5. 实际交付情况（2026-08-07 回填）

> ★本节是**事后订正**，不是计划★。上面的分期是当初的设想，实际动手时没有严格按它走 ——
> 与其让文档继续说一个不存在的顺序，不如把真相写下来。文档是给后来人看的。

### 5.1 交付到哪儿了

| 期 | 已交付 | 还缺 |
|---|---|---|
| **M1** | 全部（含 M1 收口的通知与 owner 转移，v0.4.26/v0.4.27） | — |
| M2 | 建议改期、公开/私密、公开会议广场 + 旁听、移出成员 | **周期会议（RRULE）** |
| M3 | 会议材料上传、录制、自动转写、纪要页 | 项目树里的只读会议区 |
| M4 | 公开分享（含移出成员连带撤销链接） | 时间线入口、复制到自由区 |
| M5 | 个人投入统计 | 项目统计、补录到场、导出 CSV |

### 5.2 为什么会跳着走

M2~M5 里被提前做掉的那些，多数**不是主动加塞**，而是原型里画了、
按原型补齐 UI 时顺手一起实现的（见 `docs/UI-GAP.md`）——
原型是按完整产品画的，照着它补就自然越过了分期线。

**这不是没有代价的**：功能横着铺开，而**没有任何一期经过相位 6 的正式验收**。
2026-08-07 那个「超管一场会都看不到」的 SQL 括号 bug、以及同一天发现的
「删掉项目后它的会议还留在日历上」，都是**用户和截图**发现的，不是测试。
教训写在这里：★宽度不能代替深度★，铺得越宽，没验过的面积越大。

### 5.3 一处与原文档相反的现实

§3 的「问题 5」说 M1/M2 的会议详情页**不要显示材料区**（免得用户问「材料在哪传」）。
**实际上材料区在 M1 就有了** —— M3 的能力（上传、转写、纪要）本来就是 P1~P2 的存量，
接上会议只是加一层关联，没有理由藏起来。那条处置作废。
