## 1. 平台服务：★我实测过了，可用★

| 项 | 实测 |
|---|---|
| 地址 | `latex-svc.platform.svc:8000`（`platform` ns，2 副本，已跑 12 天） |
| 网络 | ★`subsystems` 在它的 NetworkPolicy 放行名单里★ —— congrove 的 pod 直接连得上；它自己 **egress 全禁**（正是 D15 要求的安全边界） |
| 接口 | `POST /compile-md`（multipart）与 `POST /compile`（.tex） |
| 实测 | 一份中文 Markdown（标题/粗斜体/表格）→ **HTTP 200 / 3.2s / 28KB 真 PDF**，★中文渲染完全正确，无豆腐块★ |

⚠★契约有一个坑，写下来别再踩★：服务自己的用法串写的是 `files[]=…`，
**但实际的 multipart 字段名是 `files`**（那个 `[]` 是说明不是字面量）。我照抄第一次就 400。

⚠ 已知的两处不足（不阻塞，记着）：行内 `code` 没渲染成等宽；版式是 pandoc 默认（页边距大）。
要改就走服务的 `template` 参数，那是**下一轮**的事。

## 2. 决定

### D-1 ★随时可导出，草稿导出的 PDF 自己带「草稿」标记★

liaoruili 选了「随时可导出（草稿也能）」。⚠ 这与 `0001_init.sql` 里那条设计的**理由**冲突：

> `pdf_item_id`：点「完成」时经 LaTeX 生成 PDF 存档为一条 items。★内容冻结★：事后改纪要不会悄悄改变已经发出去的那份 PDF。

那条的顾虑是「未定稿被当正式件发出去」。★解法不是拒绝需求，是让那份文件**自己说明身份**★：
`status = draft` 时在 PDF 抬头显著位置印 **「草稿 · 尚未定稿」**。

**为什么这样就够**：「内容冻结」这个性质其实是**逐份**成立的 —— 每次导出都是一次快照，
发出去的那一份永远不会被后来的编辑改动。原设计真正想防的是**混淆**，而水印直接解决混淆。
★靠人记得「这份是草稿」是不可靠的；靠文件自己带标记是可靠的。★

### D-2 一条 item，多个版本

`pdf_item_id` 是**单个** FK。所以：
- 首次导出 → 建一条 item（落在活动材料里，名字 `<活动标题>-纪要.pdf`），回填 `pdf_item_id`；
- 再次导出 → ★写成同一条 item 的**新版本**★（`item_versions`），不新建行。

这正是 schema 注释里「可下载/分享/**进版本历史**」的那半句。
⚠ 好处不只是整洁：一条稳定的 item id 意味着**分享链接不会因为重新导出而失效**。

### D-3 同步生成，不做任务队列

实测 3.2s。同步的代价是请求要等，好处是**用户当场知道成没成**。
⚠ 真正的理由是：★这里没有「先返回再慢慢做」的收益★ —— 用户点导出就是要立刻拿到那份文件。
转写走队列是因为它要几分钟；这个不是。
超时给 120s，超时/失败的文案**按阶段说人话**（沿用 `job-error.ts` 那次的教训，别把上游 JSON 糊给用户）。

### D-4 权限 = 能写纪要的人

`require_activity_host`（发起人 / 记录员 / 超管）——与 `minutes_put` **同一个判据**。
⚠ 不放宽给普通参会人：导出是**产出正式文件**，不是读。

## 3. 契约

```
POST /api/activities/{id}/minutes/pdf     发起人 / 记录员
  200 { "item_id": 123, "version": 2, "draft": true }
  502 上游编译失败 → { "error": "<带行号的日志片段，截断>" }
```

前端：纪要页「下载 PDF」旁边加「导出 PDF」；已有 `pdf_item_id` 时显示「重新导出」。

## 4. 拼给 latex-svc 的 Markdown

由**后端**拼（不是前端）——★同一份纪要在任何入口导出都必须是同一份文件★：

```
# <活动标题>                      ← status=draft 时前面加 “【草稿 · 尚未定稿】”
**时间**：… **地点**：… **线上**：…
**记录员**：…  **到场**：… **旁听**：… **缺席**：…
## 议程        ← agenda_text 非空才出
## 主要内容    ← content_md（记录员写的 Markdown，原样嵌入）
## 决议事项    ← resolutions
## 待办事项    ← todos
```

⚠★空段落不出标题★：一个只有标题没有内容的「决议事项」，读的人会以为内容丢了。
