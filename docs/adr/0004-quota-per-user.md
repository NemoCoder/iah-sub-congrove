# ADR-0004：配额从项目挪到人；`user_quota` 与 `user_prefs` 拆两张

**状态**：已定（PRD L3 / J2 已回填，liaoruili 2026-08-08） · **实施**：M0-6（★「钱」路径★）

## 决定

1. 删 `projects.quota_bytes`，新增 `user_quota`（`username` 主键）；
2. 用量**算项目 owner 的**，汇总他名下**所有项目** —— 不是按单个项目、也不是按上传者；
3. ★同一 owner 内按 blob 去重，只算一份★；跨 owner 各算各的；
4. `user_quota` 与 `user_prefs` **拆成两张表**。

## 为什么

**挪到人**：额度是给人的资源，不是给项目的。挂在项目上，建一个新项目就白得 10GiB。

**算 owner 不算上传者**：口径改过一次（原来按 `created_by`）。按上传者的话，
项目主持人可以拉一堆人来传东西，占的是别人的额度 —— 而材料是他的。

**同 owner 去重**：实现就是配额 SQL `GROUP BY s3_key`（★不带 `project_id`★）。
内容寻址已经让同内容全库只存一份，同一个人把同一份材料放进两个项目还算两遍，是在收他没花的钱。
跨 owner 不去重，否则谁先传谁吃亏。

**拆两张表的理由是写权限不同**：偏好（时区、默认提醒）**用户自己改**，配额**只有超管能改**。
放同一张表意味着一条 `UPDATE` 路径要在字段级分权 —— 那是漏权的经典长法。

## 「没有行」的语义先定死

| 表 | 无行 = | 读法 |
|---|---|---|
| `user_quota` | 用系统默认 `DEFAULT_QUOTA_BYTES` | ★不是 0★ —— 新用户不该一上来就超额 |
| `user_prefs.timezone` | **没有默认**（PRD E0「不设默认北京」） | 由前端按浏览器时区显示，服务端不猜 |

⚠ `user_quota.quota_bytes` 的默认值与 `config.rs` 的 `DEFAULT_QUOTA_BYTES` **必须同步** ——
两处写死同一个数是已知的重复，改一处要改两处。

## 结构后果（写出来，不藏着）

配额跟着 owner 走，所以**转移主持人 = 连同配额一起转**（`POST .../transfer`）。
接收方可能当场超额。已定的处置：**超额只能删，不能再传**（不做拒收，也不做宽限期）。

## 门禁

删列的是 M0-6 那个 PR，所以 ★schema 闸跑在删列的那次★（不是提前跑在还没删的 PR 上）。
配额语义要 6 条 E2E（按 owner 汇总 / 版本历史计入 / 半截直传不计 / 新用户无行走默认 /
回收站仍计入 / 超额只能删），★现在只有 1 条，M0-6 必须先补测试再改实现★。

## 不管什么

不管超管调额度的 UI（有 API 就够，M0 不做页面）；不管配额告警。
