# 权限模型调研与设计决策(2026-08-02,三路联网深调研)

> 起因:用户对「小组/空间成员为什么分开」提出质疑,并要求对标成熟产品深度调研
> (角色、小组、空间从哪来;谁能建组/建空间;文档级读写权限做不做)。
> 三路并行调研 Confluence(官方文档)、Notion+SharePoint、飞书+钉钉知识库(中文团队事实标准),
> 本文是交叉综合。**改权限模型前必读本文;推翻任何「共识」条目须先有新证据。**

## 一、三家模型速览

| | Confluence | Notion | 飞书知识库 | 钉钉知识库 | congrove 现状 |
|---|---|---|---|---|---|
| 容器 | Space | Teamspace | 知识库 | 知识库(可挂群) | 空间 |
| 容器角色 | 权限矩阵 10+ 项逐项勾 | owner/member+四档 | **管理/编辑/阅读 3 档** | 4 档(+仅可查看防泄漏) | viewer/editor/admin 3 档 |

## 二、跨三路的共识(不再争论,直接作为汇流的定案)

1. **组与空间分离、空间只存授权引用**是全行业结构:组=人的集合(跨空间复用),空间授权=(组或人→角色),
   按当前组成员**动态求值**——「入职只改组成员」是这套结构的核心运维收益(Confluence 官方最佳实践原话)。
   汇流现状正确,保持。
2. **三档打包角色是认知上限**(飞书 3 档被中文用户大规模验证;SharePoint 10 级 permission level 是反例,
   官方也只推 3 组 3 档)。逐项 ACL/自定义级别**坚决不做**;比档位细的需求(下载/导出/评论)
   将来收进「空间安全开关」,不加角色。
3. **additive、无 deny**:同一人多来源授权取最强;负权限(组授权+个人降级)是 SharePoint 式失控的
   第一张多米诺,三家都没做,我们也不做。
4. **空间级是权限主战场,文档级是例外通道**:SharePoint 给了 item 级自由,微软官方文档开篇劝
   「don't break inheritance」,唯一权限作用域还有 5 万上限/5 千性能红线——事后崩溃证明要事前约束。
   中文团队习惯更干脆:**库内要隔离 = 再建一个库**,不在一个库里切区。
5. **建容器者自动成为其管理员** + 平台级超管兜底(高校场景导师流动/学生毕业,必须有超越单库管理员的
   治理层——飞书为此专设「知识库功能管理员」)。汇流的 is_super 即此层。
6. **权限诊断是刚需**:「为什么他看得到/看不到」三家都是痛点,Confluence 把排查工具做成 Premium 付费
   卖点。汇流的 effective_role 是唯一推导点,做诊断 API+UI 成本极低,应内建(P3)。

## 三、汇流现状对照:对的与缺的

**已对齐共识**:两层结构、三档角色、动态组授权、additive 取 max、建者即 admin、超管兜底、
解散组时显式清除该组全部空间授权(比飞书「移除成员不影响单页协作者」更干净)、
防锁死闸(最后一个 admin/manager 不可降/删)。

**缺口(按共识排序)**:
- 无「谁能建空间」开关(三家都有或建议收窄);
- 无权限诊断(共识 6);
- 无空间安全开关(viewer 禁下载/导出——钉钉做成档位、飞书做成开关,研究组未发表数据场景真实);
- 文档级权限留白(是否补、补成什么形态 = 决策点 3)。

**UI 教育缺口**:「组授权给空间」这一核心动作藏在授权管理弹窗里,用户没意识到
「选组→授权=整组人(含未来成员)一次进来」——要在空间授权 UI 里把「小组」选项提为默认+文案说明。

## 四、决策点(需用户拍板;附三家做法与推荐)

**D1 谁能建小组?**
- Confluence 仅管理员(被抱怨最狠);Notion member 可建;飞书没有自助组。
- 推荐:**维持全员自助**(建者=manager)——改进 Confluence 痛点,符合研究组「导师/学生自组织」;
  超管已可见全部组兜底。备选:加开关收紧到仅超管。

**D2 谁能建空间?**
- 三家全部提供收窄手段;高校场景空间泛滥风险真实(Atlassian 最佳实践:只授少数「冠军」用户)。
- 推荐:**加环境变量开关 `CONGROVE_SPACE_CREATORS`**(空=全员可建;填用户名列表=仅名单+超管可建),
  默认全员,泛滥了再收——一行判定的成本。

**D3 文档级权限做不做?**
- 中文习惯:不做,「要隔离再建一个空间」(最便宜、零排查成本);
- 若做,唯一不失控的形态是 Notion 式:**整节点白名单覆盖**(view 向下继承整棵子树、编辑档不继承)+
  「受限」徽标 + admin 有全空间受限清单可强制解除 + 每空间受限节点数上限(把 SharePoint 的
  事后崩溃变成事前约束);**绝不做**「组授权+个人排除」的减法。
- 推荐:**v1 不做,先靠"再建空间"**;真实需求出现(如「组会空间里的经费页只给导师」)再按上述形态
  实施为 P3+(schema 口子 item_grants 一直留着)。

**D4 viewer 防泄漏(禁下载/复制导出+水印)?**
- 钉钉内置档位、飞书全库开关,中文场景强需求;但 congrove 当前内容以录屏/论文为主,
  「能看就能录屏幕」,防泄漏对内网研究组的边际价值存疑。
- 推荐:**P3 做成每空间开关「viewer 禁下载原件」**(下载路由一行判),水印不做。
