## 二、本轮发现

### ★阻塞 1★ · `settings.rs::读原始值` 把「没查成」吞成「没设过」→ 建项目白名单静默失效

```rust
.bind(key).fetch_optional(pool).await.ok().flatten()   // ← DB 错误变成 None
```

`None` 在 `effective_project_creators` 里的兜底是 **空名单 = 人人可建**（这是 liaoruili
2026-08-16 拍板维持的产品行为，本身没错）。两者一叠加：

> ★数据库抖一下，「谁能建项目」这道治理闸就静默失效，而且没有任何日志。★

同一个吞法也让 `effective_default_quota` 悄悄回落到编译期常量 ——
而它是 `owner_quota_used` 的 `COALESCE` 兜底，**所有没单独设过配额的人当场跟着变**
（dev 上 108/108 都没设过）。

**已修**：`读原始值` 改回 `Result`，三个 `effective_*` 全部传播错误。
「值写坏了」仍然回落默认（那是**查到了但内容不合法**），「没查成」一律让请求失败。
★这是本仓反复吃亏的同一条的第三种形态★：把「我没查」当成「查了没问题」，
在权限路径上就是 fail-open。

### ★阻塞 2★ · `reclaim_stale` 无条件回收 running → 每次滚动更新都可能重跑正在进行的转写

```sql
UPDATE media_jobs SET status='queued' WHERE status='running'   -- 无条件
```

`claim_job` 的注释写着「`FOR UPDATE SKIP LOCKED` 保证**多副本**时不会取到同一条」——
代码是按多副本设计的。而无条件回收在多副本下会把**别的副本正在跑的**任务打回队列。

★单副本也躲不掉★：k8s 滚动更新期间新旧 pod 并存，新 pod 一启动就把旧 pod
正在转写的那条打回 queued、自己重跑。**每次部署都可能白烧一次 GPU**，
而现象只是「这次转写慢了点」。

**已修**：判据改成心跳（`updated_at` 超过 15 分钟没推进才回收，`stage()` 每步都写它）。
顺带修了 2026-08-16 那段注释自己点出的另一半 —— `reclaim_stale`
**只在启动时跑一次**，于是进程活着、任务卡死时连回收都等不到。现在每轮都跑。
⚠ 代价：进程被打断时那条任务要等 15 分钟才重排（原来是立刻）。
「慢 15 分钟」远好过「每次部署重跑一段录音」。

### issue 3 · `respond` 的两步写没有事务 → 责任可能悬空

答复（`UPDATE activity_participants`）与「记录员拒绝出席 → 纪要转回发起人」
（`UPDATE activities SET recorder`）是两条独立的 UPDATE。第一条成功、第二条失败时：
**他记成了 declined，而 recorder 还挂在他名下** —— 系统会一直催他写一场他明说不去的会的纪要，
而这正是那段自动转移要消除的东西。

**已修**：两步包进一个事务，★notify 挪到 commit 之后★
（事务里发信的话，一旦回滚就是「信说纪要转给你了，而库里没转」）。
⚠ `counter` 分支的 notify 仍在 commit 前 —— 它不写库、风险小一个量级，
而挪它要重排整个函数。★权衡记在代码注释里，没有当成没看见。★

### issue 4 · 前端 7 处 `.catch(() => {})`，其中一处让表单静默不可用

`activity-new.tsx:125` 加载活动类型失败 → 下拉是空的，而**类型是必填且决定整张表单的形状**。
屏幕上不说任何话。这是本仓反复出现的「安静地不工作」。
**未修**（记账）：改法要连带想清楚「加载失败时整个表单要不要禁用」，是产品判断。

## 四、本轮固化成门禁的（审计的复利在这里）

★`scripts/authz-coverage.sh`（第 21 道闸）★ —— 每个写接口都必须有权限调用。

漏判权是本仓最严重的一类缺陷（A1 就是），而在此之前**没有任何东西守着它**：
clippy 不管、类型不管、shape-check 只看形状，新加一个 POST 忘了 `require_*`，门禁照样全绿。

⚠★这个脚本自己被审计出过两个 bug，都记在它的头注里★：

1. 初版按**函数名全树搜** —— `storage.rs` 里也有 `pub async fn copy(`，先被命中，
   于是检查的是**错的那个函数**，`items::copy` 被误报成漏判权。
   ★一个会漏报的审计工具比没有更坏★：它给的是虚假的安心。
2. 守卫定义太窄（只认 `require_role` 那几个）→ 12 条**合法**接口被报成漏判权。
   ★一道会误报的门禁会被人忽略，等于没有★。现在它抓的是
   「**完全没有**任何权限考虑」，并且认路由层的 `route_layer(require_super)`。

已验证它是活的：注入一个没判权的 `POST /裸奔` → 立刻报红。
